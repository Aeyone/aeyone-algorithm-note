<a id="problem"></a>
## 题意

有 `n` 个城市，第 `i` 个城市传送强度为 `a[i]`。

从城市 `p` 出发：

- 如果 `p + a[p] > n`，这次传送后到达终点；
- 否则传送到 `p + a[p]`；
- 如果原城市 `a[p] > 1`，传送后 `a[p]--`。

给出 `m` 次出发点，依次执行，输出每次需要多少次传送。

<a id="bad"></a>
## 为什么不能普通模拟

如果所有 `a[i] = 1`，每次从 `1` 出发都要走：

```text
1 -> 2 -> 3 -> ... -> n -> 终点
```

单次是 `O(n)`，`m` 次就是 `O(nm)`，会超时。

所以真正要优化的是：

```text
如何快速跳过连续的 a[i] = 1 的区间
```

<a id="core"></a>
## 题解核心

把访问分成两类：

- 访问 `a[x] > 1` 的点；
- 访问 `a[x] = 1` 的点。

对于 `a[x] > 1` 的点，直接模拟：

```text
to = x + a[x]
a[x]--
x = to
```

这类访问总量可以接受。题解的直觉是：每访问一次大于 `1` 的点，它的能量就会下降；所有点从大值降到 `1` 的总次数可以用距离贡献证明在 `O(n√n)` 量级。

真正会炸的是 `a[x] = 1`：

```text
x -> x+1
```

如果一段全是 `1`，逐个走就会很慢。

所以遇到 `1` 时不要一步一步走，而是直接跳过整段连续的 `1`。

<a id="dsu"></a>
## DSU 维护连续 1 段

更简单的写法是“删除式并查集”。

维护：

```cpp
find(x) = 从 x 开始，第一个 a[pos] > 1 的位置
```

如果从 `x` 到 `n` 都没有大于 `1` 的点，就返回哨兵：

```cpp
n + 1
```

这样当 `a[x] == 1` 时：

```cpp
to = find(x)
ans += to - x
x = to
```

含义是：从 `x` 到 `to-1` 全都是 `1`，所以这一整段可以一次跳过。

初始化从右往左做：

```cpp
fa[n + 1] = n + 1

for i = n ... 1:
    if a[i] > 1:
        fa[i] = i
    else:
        fa[i] = fa[i + 1]
```

例如：

```text
a = [3, 1, 1, 4, 1]
```

那么：

```text
find(1) = 1
find(2) = 4
find(3) = 4
find(4) = 4
find(5) = 6
```

当某个位置 `x` 从 `2` 变成 `1` 时，说明它以后也应该被跳过，于是把它“删除”：

```cpp
fa[x] = find(x + 1)
```

也就是让 `x` 直接指向右边第一个还大于 `1` 的位置。

核心模拟：

```cpp
if (a[x] > 1) {
    ans++;
    int to = x + a[x];
    a[x]--;
    if (a[x] == 1) activate(x);
    x = to;
} else {
    int to = find(x);
    ans += to - x;
    x = to;
}
```

注意这里不需要真的维护 `[l,r]` 的左右端点。`find(x)` 已经等价于直接跳到当前连续 `1` 段的右端点后一位。

<a id="trick"></a>
## 技巧总结

这个技巧可以叫“删除式并查集”。

它维护的是：

```cpp
find(x) = 从 x 开始，右边第一个还没被删除的位置
```

删除一个位置 `x` 时：

```cpp
fa[x] = find(x + 1)
```

意思是：以后再查询 `x`，直接跳到 `x+1` 右边第一个还没被删除的位置。

通用模板：

```cpp
fa[n + 1] = n + 1;

for (int i = n; i >= 1; i--) {
    if (alive[i]) fa[i] = i;
    else fa[i] = fa[i + 1];
}

int find(int x) {
    while (fa[x] != x) {
        x = fa[x] = fa[fa[x]];
    }
    return x;
}

// 删除 x
fa[x] = find(x + 1);

// 查询 x 右边第一个未删除位置
int pos = find(x);
```

适用场景：

- 位置只会从“可用”变成“不可用”，不会变回来；
- 需要频繁查询右边第一个可用位置；
- 想用比 `set.lower_bound` 更低常数的做法。

本题中：

```cpp
未删除 = a[i] > 1
已删除 = a[i] == 1
```

所以当 `a[i]` 从 `2` 变成 `1` 时，就执行：

```cpp
fa[i] = find(i + 1)
```

之后再走到 `i`，就会直接跳过这段连续的 `1`。

<a id="proof"></a>
## 复杂度证明

关键是证明：

```text
所有 a[x] > 1 的访问总次数是 O(n√n)
```

先只看大于 `1` 的访问。

如果某个位置当前能量是 `v > 1`，访问它一次会：

```text
从 x 跳到 x + v
并让这个位置的能量变成 v - 1
```

也就是说，这次访问至少贡献了 `v` 的前进距离。

题解用“所有询问的总距离”来限制访问次数。每一次旅行最多从某个 `b_i` 走到 `n+1`，所以单次前进距离不超过 `n`。又因为 `m` 和 `n` 同阶，所以所有询问的总前进距离是：

```text
O(n²)
```

现在看某一个位置。

假设它的大于 `1` 的访问过程中，能量从 `A` 降到 `B`，其中 `B >= 1`。

它贡献的距离至少是：

```text
A + (A-1) + ... + (B+1)
```

这个和是：

```text
A(A+1)/2 - B(B+1)/2
```

如果记这个位置被大于 `1` 访问了 `t = A - B` 次，那么距离贡献大约是一个二次量：

```text
1 + 2 + ... + t = t(t+1)/2
```

所以一个位置如果被访问很多次，就必须消耗很多总前进距离。

把所有位置的大于 `1` 访问次数记成：

```text
t1, t2, ..., tn
```

那么有：

```text
Σ ti² = O(n²)
```

因为所有位置的距离贡献总和不超过 `O(n²)`。

接下来用平方和控制总次数：

```text
(Σ ti)² <= n * Σ ti²
```

所以：

```text
Σ ti <= √(n * O(n²)) = O(n√n)
```

这就说明：

```text
所有 a[x] > 1 的访问总次数是 O(n√n)
```

剩下的问题是 `a[x] = 1`。

如果普通模拟，`1` 不会减少，会被反复走，可能退化成 `O(nm)`。

用删除式并查集后，每次遇到连续 `1` 段，只会做一次：

```text
find(x)
```

而相邻两次跳 `1` 段之间，必然会访问某个 `a[x] > 1` 的点，或者直接结束。

所以 `find` 次数也被 `O(n√n)` 级别控制。

<a id="others"></a>
## 其他做法

### 1. 线段树找下一个 `>1`

可以维护区间最大值，然后二分找下一个 `a[pos] > 1` 的位置。

但这样每次跳过 1 段需要：

```text
O(log² n)
```

本题数据下容易比 DSU 慢很多。

### 2. set 维护所有 `a[i] > 1` 的位置

维护一个有序集合 `alive`，里面存所有 `a[i] > 1` 的位置。

当遇到 `a[x] = 1`：

```cpp
it = alive.lower_bound(x)
to = *it 或 n+1
ans += to - x
x = to
```

当某个位置从 `2` 变成 `1` 时，从 `alive` 删除它。

这个做法也能过，复杂度大概是：

```text
O(访问大于 1 的次数 * log n + m log n)
```

比线段树二分简单，但常数和复杂度一般仍不如 DSU。

### 3. 分块

可以用 sqrt decomposition 维护跳转结果，但因为 `a[i]` 会动态递减，维护比较麻烦，没有 DSU 直接。

<a id="complexity"></a>
## 复杂度

DSU 做法中：

- 访问 `a[x] > 1` 的总次数由题解证明为 `O(n√n)`；
- 每次变成 `1` 最多 activate 一次；
- 每次遇到 `1` 段只做一次 `find`。

总复杂度约为：

```text
O(n√n α(n))
```

空间复杂度：

```text
O(n)
```
