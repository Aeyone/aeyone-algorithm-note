## 题意

有 $n$ 名同学在时刻 $t_i$ 到达车站。摆渡车容量无限，每次从车站出发、送到目的地、再回到车站总共需要 $m$ 分钟。可以任意安排发车时间，要求把所有同学送走，并最小化所有同学的等待时间总和。

<a id="core-dp"></a>
## 核心 DP

先把到达时刻整体加 $1$，代码中用 `c[i]` 表示到达时刻不超过 `i` 的人数，用 `s[i]` 表示这些到达时刻的总和。

设 `dp[i]` 表示最后一班车在时刻 `i` 发车，并且已经送走所有到达时刻不超过 `i` 的同学时的最小等待和。

如果上一班车在 `j` 发车，那么下一班车在 `i` 发车必须满足：

$$
j \le i - m
$$

此时 `(j, i]` 中到达的同学都等到 `i` 上车，贡献为：

$$
i(c[i]-c[j])-(s[i]-s[j])
$$

所以转移为：

$$
dp[i]=\min_{j \le i-m}\{dp[j]+i(c[i]-c[j])-(s[i]-s[j])\}
$$

<a id="cht"></a>
## 凸包优化

把和 `j` 有关的部分拆出来：

$$
dp[i]=i \cdot c[i]-s[i]+\min_j\{dp[j]+s[j]-i \cdot c[j]\}
$$

对当前横坐标 `i`，每个合法的 `j` 相当于一条直线：

$$
y=-c[j]x+dp[j]+s[j]
$$

因为 `c[j]` 单调不减，所以斜率单调；查询的 `i` 也单调递增，因此可以用单调队列维护凸包。

关键点是：状态 `j` 不是算出来就能立刻转移给后面，它要等到当前时间 `i >= j + m` 时才合法。因此每轮应该把 `k = i - m` 插入凸包，再查询当前 `i`。

<a id="bug"></a>
## i.cpp 的问题

`ii.cpp` 的顺序是正确的：

```cpp
k = i - m;
if (k >= 0) {
    把 k 按凸包规则插入队尾;
}
用凸包队首查询 dp[i];
```

`i.cpp` 的主要问题是把“延迟合法”和“凸包插入”拆坏了：

```cpp
while (que.size() && que.front() <= i - m) {
    q.push_back(que.front());
    que.pop();
}
```

这里把刚刚变合法的候选点直接 `push_back` 进 `q`，没有做凸包维护。这样 `q` 已经不再保证是一个正确凸包。

更严重的是后面这段：

```cpp
que.push(i);
int k = q.front();
while (...) {
    q.pop_back();
}
```

这里真正新产生的候选点是 `i`，但它还不能马上加入凸包；而代码却拿 `q.front()` 当作新点 `k` 去维护队尾。这等于用队首元素去删队尾，逻辑完全不对应凸包插入规则，会删掉本来有用的线，也可能留下无用线。

所以 `i.cpp` 错不在 DP 式子，而在凸包队列维护：`q` 不是合法凸包，查询 `q[0]` 得到的 `j` 不一定是最优。

<a id="complexity"></a>
## 复杂度

每个时刻最多进队、出队一次，时间复杂度为 $O(T)$，其中 $T$ 是枚举的最大时间范围。空间复杂度为 $O(T)$。
