<a id="statement"></a>
## 题意

有 `n` 个盘子，每个盘子初始有 `1`、`2` 或 `3` 个寿司。每次等概率随机选择一个盘子，如果这个盘子还有寿司，就吃掉一个；如果没有寿司，这次操作什么也不发生。

问吃完所有寿司的期望操作次数。

<a id="state"></a>
## 状态定义

只关心还有多少盘子分别剩下 `1`、`2`、`3` 个寿司。

设 `dp[i][j][k]` 表示：

- 有 `i` 个盘子剩 `1` 个寿司。
- 有 `j` 个盘子剩 `2` 个寿司。
- 有 `k` 个盘子剩 `3` 个寿司。
- 从这个状态开始，吃完所有寿司的期望操作次数。

终点：

$$
dp[0][0][0]=0
$$

<a id="similar"></a>
## 和集齐骰子的相似点

这题和“集齐骰子所有面”很像：不是每一次操作都有用。

当前还有寿司的盘子数量是：

```text
alive = i + j + k
```

一次操作选到有寿司盘子的概率是：

```text
alive / n
```

所以平均要操作：

```text
n / alive
```

次，才会真正吃掉一个寿司。

这就是为什么最终转移里会出现除以：

$$
\frac{i+j+k}{n}
$$

也可以理解成每次状态真正变化前，要先等待一次“选中非空盘子”的成功事件。

<a id="transition"></a>
## 转移推导

从状态 `(i,j,k)` 出发，一次随机操作后：

- 选到剩 `1` 个寿司的盘子，概率 `i/n`，状态变成 `(i-1,j,k)`。
- 选到剩 `2` 个寿司的盘子，概率 `j/n`，状态变成 `(i+1,j-1,k)`。
- 选到剩 `3` 个寿司的盘子，概率 `k/n`，状态变成 `(i,j+1,k-1)`。
- 选到空盘子，概率 `1-(i+j+k)/n`，状态不变。

所以：

$$
dp[i][j][k]=1
+\frac{i}{n}dp[i-1][j][k]
+\frac{j}{n}dp[i+1][j-1][k]
+\frac{k}{n}dp[i][j+1][k-1]
+\left(1-\frac{i+j+k}{n}\right)dp[i][j][k]
$$

<a id="move"></a>
## 为什么要移项

因为可能选到空盘子，状态会回到自己，所以等式右边也有 `dp[i][j][k]`。

把它移到左边：

$$
\frac{i+j+k}{n}dp[i][j][k]
=1
+\frac{i}{n}dp[i-1][j][k]
+\frac{j}{n}dp[i+1][j-1][k]
+\frac{k}{n}dp[i][j+1][k-1]
$$

所以代码里先把右边加起来，再除以：

$$
\frac{i+j+k}{n}
$$

也就是：

```cpp
dp[i][j][k] /= double(i + j + k) / n;
```

<a id="order"></a>
## 枚举顺序

转移依赖：

```text
(i,j,k) 依赖 (i-1,j,k)
(i,j,k) 依赖 (i+1,j-1,k)
(i,j,k) 依赖 (i,j+1,k-1)
```

因此当前代码按：

```cpp
for (int k = 0; k <= n; k ++)
    for (int j = 0; j <= n; j ++)
        for (int i = 0; i <= n; i ++)
```

可以保证依赖状态已经算过：

- `i-1` 已经在当前 `i` 之前算过。
- `j-1` 已经在当前 `j` 之前算过。
- `k-1` 已经在当前 `k` 之前算过。

<a id="complexity"></a>
## 复杂度

状态数是 $O(n^3)$，每个状态 $O(1)$ 转移。`n <= 300` 时可以通过。空间复杂度也是 $O(n^3)$。
