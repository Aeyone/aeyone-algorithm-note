# D. Reserved Reversals

## 结论

设奇数子序列和偶数子序列分别按原顺序取出。

长度为 `2` 的合法反转等价于交换一对相邻的奇偶数，所以：

- 奇数可以穿过偶数；
- 偶数也可以穿过奇数；
- 但只靠这种交换，奇数内部相对顺序不变，偶数内部相对顺序也不变。

因此，真正要判断的是：**同奇偶性内部的逆序对能不能被修正。**

对于一个同奇偶性的逆序对 `x > y`，想把它修掉，必须存在一个相反奇偶性的“助手” `z`，满足：

- `z < y`，或者
- `z > x`

否则任何包含 `x, y` 的可反转区间，其最小值和最大值都会和 `x, y` 同奇偶，区间就不合法。

## 正确判据

只看一种奇偶性，比如奇数。

记相反奇偶性的全局最小值、最大值为：

- `oppMin`
- `oppMax`

从左到右扫描奇数，维护此前出现过的奇数最大值 `mx`。

当前奇数是 `y`：

- 如果 `mx <= y`，没有新逆序；
- 如果 `mx > y`，说明出现了某个逆序对 `(mx, y)`，此时必须满足：

```text
oppMin < y  或者  oppMax > mx
```

偶数同理检查一遍。

时间复杂度是 `O(n)`。

## 你这份代码错在哪

对应文件：[d.cpp](./d.cpp)

### 1. 你只用了“前缀里的助手”，但正确的是“全局助手”

你在 [d.cpp:27](./d.cpp) 用的是当前扫描到位置之前的：

```cpp
mn[c ^ 1], mx[c ^ 1]
```

但助手可以在后面，不一定已经出现。

最小反例：

```text
[1, 3, 1, 4]
```

你的程序会输出 `NO`，但真实答案是 `YES`。

一种可行操作：

```text
[1, 3, 1, 4]
-> reverse [1,4]
[4, 1, 3, 1]
-> reverse [1,2]
[1, 4, 3, 1]
-> reverse [2,4]
[1, 1, 3, 4]
```

这里帮助修正逆序 `3 > 1` 的偶数助手是 `4`，它在后缀，不在前缀。

### 2. 你只看了“上一个同奇偶元素”，但正确的是“前面同奇偶元素的最大值”

你在 [d.cpp:26](./d.cpp) 用的是：

```cpp
v[c].back()
```

这只能检查“相邻的同奇偶元素”是否逆序，但真正需要防的是：

```text
前面任意一个更大的同奇偶元素
```

所以这里应该维护：

```cpp
mxSame = 之前同奇偶元素的最大值
```

反例：

```text
[2, 4, 5, 3, 1]
```

你的程序会输出 `YES`，但真实答案是 `NO`。

因为奇数子序列是：

```text
[5, 3, 1]
```

你会检查到：

- `5 > 3`
- `3 > 1`

但你漏掉了更关键的：

- `5 > 1`

而这个逆序没有可用偶数助手：

```text
偶数只有 2, 4
既没有 < 1 的，也没有 > 5 的
```

所以真实答案只能是 `NO`。

## 一句话修正

你的整体思路方向是对的，问题只在判据写窄了：

- 助手要看全局，不是只看前缀；
- 逆序要看“前面最大值”，不是只看“前一个同奇偶元素”。
